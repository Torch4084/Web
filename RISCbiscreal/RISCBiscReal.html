Executive Summary

RISCBiscReal is solved by extending the same VM memory primitive from process-memory reading to native control-flow redirection. The challenge states that the flag is located at C:\chall\flag.txt, so the exploit must cause the Windows process to read or print that file.

The final payload dynamically locates the VM context, finds the native interpreter return slot, resolves a pop rcx; ret gadget, resolves _wsystem from loaded CRT exports, writes a UTF-16 command string, and returns into a short Windows x64 ROP chain that executes type C:\chall\flag.txt.

Vulnerability Analysis

The VM's guest memory accesses are native process memory accesses. For this challenge, reading strings from the VM image is not sufficient because the flag is stored on disk. The same primitive can also write into host memory, which allows a native control-flow hijack by replacing the interpreter's saved return address.

Windows x64 calling convention places the first argument in rcx. A call to _wsystem(L"type C:\\chall\\flag.txt") therefore requires only one controlled argument. This minimizes gadget requirements while still causing the process to print the target file to stdout.

Design objectiveResolve all required native addresses dynamically and keep the final ROP chain as small as possible.

The command string is written as UTF-16LE because _wsystem consumes a wide-character command string:

data = "type C:\\chall\\flag.txt".encode("utf-16le") + b"\x00\x00"

Implementation Details

The final generator is make_real_wsystem.py. It reuses helper routines from the included support modules to assemble RV64 instructions, locate context memory, scan PE sections, and resolve exports.

  1. emit_common_discovery locates the VM context, native stack frame, return slot, and relevant module base.
  2. parse_first_section and scan_pattern scan executable code for pop rcx; ret.
  3. emit_find_export walks loaded PE export tables until it resolves _wsystem.
  4. write_wide_string stores type C:\chall\flag.txt in writable process memory.
  5. The payload writes the ROP chain at the native return slot and triggers the VM exit syscall.

class X64:
    def __init__(self):
        self.buf = bytearray()
        self.labels = {}
        self.fixups = []

    def label(self, name):
        self.labels[name] = len(self.buf)

    def emit(self, data):
        self.buf.extend(data)

    def u32(self, val):
        self.emit(struct.pack("<I", val & 0xFFFFFFFF))

    def u64(self, val):
        self.emit(struct.pack("<Q", val & 0xFFFFFFFFFFFFFFFF))

    def rip(self, opcode, label):
        self.emit(opcode)
        self.fixups.append((len(self.buf), label))
        self.u32(0)

    def resolve(self):
        out = bytearray(self.buf)
        for off, label in self.fixups:
            disp = self.labels[label] - (off + 4)
            struct.pack_into("<i", out, off, disp)
        return bytes(out), self.labels

def recv_until_idle(sock: ssl.SSLSocket, timeout: float) -> bytes:
    sock.settimeout(timeout)
    chunks = []
    while True:
        try:
            chunk = sock.recv(4096)
        except socket.timeout:
            break
        if not chunk:
            break
        chunks.append(chunk)
    return b"".join(chunks)
